# 0.1.50 P2P read fix

Observed on device: P2P data arriving, slow start, piece 3631 timeout, then playback with stutter and anomalous duration. Root cause of duration is not established.

Changes:
- Replace base APK VerifiedPieceReader and its Pieces interface with source-compatible definitions. A read crossing from verified bytes to an unavailable piece now returns its verified prefix, rather than waiting 45 seconds and discarding it on EIO. File-relative offsets and verified-piece boundaries remain enforced.
- Route the four TorrentEngine setPieceDeadline(handle, index, delay) sites through TorrentBoost.deadline. Preserve the earliest absolute deadline for overlapping requests; an urgent request may advance it. Bookkeeping is weak-keyed by handle and bounded to 4096 entries per handle.
- Keep the existing 16-piece read-ahead and 45-second missing-piece timeout. No changes to duration calculation, decoder mode, peer limits or bitrate.

Validation: 23 JVM test programs pass, APK build/signature and unique class/reference checks pass. Patch tool requires removal of exactly the old reader/interface pair and recognizes the deadline ABI before replacing calls with identical register arguments. Android/libtorrent native playback cannot be exercised in this environment. Device speed and stall improvement remain unverified.

Do not interpret the existing bridgeError field as current state: the base callback retains previous errors even after successful reads. Duration and stale diagnostic text remain follow-ups.
