## 本轮已核对证据

设备仅 OPD2401 / Android 16。测试使用本机 loopback 合成服务、合成账号和普通 H.264 视频。窗口类与解码画面分别核对，不能只凭视频请求计数断言已经播放。

| 场景 | 实测 |
| --- | --- |
| 原生失焦恢复 | 第二次 PlaybackInfo 挂起时展开通知栏，确认焦点离开。旧连接约 500ms 后关闭，收起后产生第三次请求；合计 3 次请求、1 次播放开始。实际视频帧时间 17.667→33.833s |
| Media3 失焦恢复 | 同样 3 次请求、1 次开始；旧连接约 406ms 后关闭，窗口仍为 SystemPlayerActivity。视频帧时间 15.250→30.542s |
| C4 在途取消后立即重连 | 第二次请求设为延迟25s，挂起期间按当前截图的「取消重连」并立即切健康重连。旧请求从到达到断开875ms，新请求点击前到观察到达391ms，健康对照312ms；第三次请求在原15s读取超时之前发生。继续观察超过原25s延迟，无迟到错误框、无额外重开，只有1次播放开始 |
| C2 快速连续取消 | 两次正文停顿均设20s，首字节到断开分别297ms、313ms；取消后马上重启，第三次健康请求点击前到观察到达343ms，最后五项通过、0次播放开始 |

计时包含 ADB 调用与轮询开销，不是精确 worker 退出时间。C4 的875ms是服务端所见请求存活时间（包含点击前采样），不是纯粹的点击到断开耗时。C2 本轮 configure→第三次请求296ms，两次断开均远早于20s正文恢复。其余本轮用例与最终清理正在记录，未写入通过范围。

## 测试脚本与证据边界

原始 JSON、截图与 XML 只保存在忽略目录 `deliverables/tablet-0147-boundary/`；原有 C1–C4 的记录保留在 `deliverables/tablet-0147/`。服务器管理页只保存数量，不持久化真实地址。

本轮最初进度采样误把顶端时钟当作播放时间，另有 XML 临时文件清理失败。改用独立临时文件后，控制栏仍会在 UI 树采集结束前隐藏，因此最后人工核对了两张实际视频帧内的时间戳。这些属于脚本采样问题，不算软件失败，也不凭空增加真机通过次数。

O1（原生侧栏系统返回退出播放器）、真实杜比 P5、HDR 和真实服务器转码不在本轮通过范围。
