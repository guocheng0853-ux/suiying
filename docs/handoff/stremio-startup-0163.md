# 0.1.163 Stremio低速开播排查与接力

日期：2026-10-30。基线main `5cf660e`，0.1.162 / code163。本版0.1.163 / code164。用户确认慢点为点击播放后的连接或缓冲。

## 实际证据与边界

仓库0.1.161已按做种人数和体积调整自动预选，但备用队列仍沿插件返回顺序。底座种子启动等待至少60秒，种子信息及无下载进展的底层上限为120秒。种子不经过直链4秒地址探测，因此缩短该探测不能解决这次P2P问题。

只读提取平板私有日志中的阶段和数字，没有导出地址、哈希、影片名或令牌。近期慢连接样本已有约10–14个对端，但仅约40–80 KB/s，缓存从约1 MB缓慢增长至2.5 MB后超时。该日志是在已安装0.1.162的设备上读取，事件文件可能保留更早版本，不将其强行归因于0.1.162。它支持“实际供给不足”的诊断，不证明具体运营商或插件服务器有故障。

另一次匿名只读核对确认，历史慢连接处于27个备用源中的第2项，说明当时存在后续候选；这支持调整备用顺序和低速停留策略。

## 改动

- 用户选中的第一项保持不变。备用列表中，先排除纯DV风险，再优先安全HTTP直链，其余按既有片源/做种/体积/音轨评分稳定排序。底座仍按哈希和文件编号去重。评分预先计算，排序比较不反复解析片源文字。
- P2P下载统计每秒在后台读取，不在UI线程等待网络。仅未出画面、尚未真正开始推进、当前窗口有焦点、未暂停、自动换源已开且确有下一项时考虑接力。
- 文件真实大小和影片时长均已知、已拿到种子信息、连续15秒低于预计平均码率的65%、启动时间达到 `max(30秒, 用户等待秒数)`，且已验证缓存少于 `min(8 MiB, 预计码率×20秒)` 时调用原播放器的失败/换源路径。
- 时长或统计未知、瞬间速度波动、缓存足够、用户设了更长等待、已经播放、关闭自动换源或无备用源都保持原行为。播放代次/源对象和当前引擎均核对，晚到统计不作用于新片源。
- 可选监测的异常被隔离，继续沿底座原有超时机制处理。没有增加连接数或上传上限，没有声称提升真实种子的供给带宽。

## 验收方法

完整构建、测试、最终APK哈希与清理结果见[脱敏汇总](stremio-startup-0163-summary.json)。平板为OPD2401 / Android16；手机本轮未操作。

Android集成测试只访问本机合成HTTP服务：显式选中的延迟源、快直链和一个不被启动的占位种子。为隔离真实BT网络，在延迟源上预置合成P2P标记、31秒启动时间、连续16秒低速窗口及50 KB/s/预计300 KB/s统计，调用正式统计回调。没有连接真实种子，也没有冒充真实等待31秒、端到端BT测速或P2P首帧加速测量。

核对第一项保留、快直链排在第2项、正式换源后VLC实际出画面且时间推进；种子信息未知、速度足够、时长未知、自动换源关闭、已出画面、晚到回调及无备用源分别验证不切换。该结果证明接力与保护条件，不等于所有实际片源都更快。

2. 首次截图未取得UiAutomation活动节点，被场景安全检查拒绝；不截取其他应用或扩大采集范围。复跑改用播放器状态、队列与时间推进作为证据，未将截图失败算作播放失败。

恢复过程保留原服务器与观看记录，删除合成条目、恢复记录和临时工具，移除仅本轮38020 forward/38021 reverse，停止合成服务，核对字体、密度、方向、输入法、night mode、无障碍与测试前一致。真实杜比/HDR、真实服务器转码及新版本实际BT吞吐不在本轮通过范围。
