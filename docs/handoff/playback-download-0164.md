# 0.1.164 播放页下载与批量下载

日期：2026-10-30。基线 main `5faeac9`，0.1.163 / code 164。本版 0.1.164 / code 165。

## 入口

- **VLC 播放页，以及走 SystemPlayback 的系统解码**：`PlayerOverlay` 的「更多」第一项「⬇ 下载这一集」。这两条播放路径共用这一份菜单。
- **内置杜比 Media3**：`SystemPlayerActivity` 的「更多」由 `Media3Controls.more` 弹出，同一项加在最上面。
- **Emby 剧集季详情**：季胶囊下面、「批量下载」。选集长按「⬇ 下载这一集」不动。电影 / 单集详情原有的「⬇ 下载」不动。
- **影视仓** `FusionLibraryActivity`：多集时，线路下面、选集格上面有「批量下载」。选集长按 `OfflineDownloads.fusion(...)` 不动。单集不显示批量入口。

当前集：Emby 用这一季里看了一部分的那一集，否则第一条没看完的；影视仓用这一线路里有播放进度的最后一集，否则第一集。「从当前集往后全部」含当前集。

## 行为

- 能下的直链按现有 `OfflineDownloads` / `OfflineService` 入队。Emby 仍取原文件地址；只允许转码时用 `OfflineQueueRules.TRANSCODE`（和原先详情页同一句中文）。影视仓若当前地址已是可下的 http 文件，就下这个地址并记下线路，方便过期后续传；否则按长按那条路径重新解析。
- 磁力 / 种子（含 `infoHash`）、m3u8、DASH 用 `OfflineRules.refuse` 的原句。播放页把这一项置灰，副标题写原因，点一下再提示，不静默失败。临时的 `127.0.0.1` 地址在还能向 Emby 或影视仓重取时不挡住，否则提示地址只在播放时有效。
- 已完成、排队、下载中、暂停都不重复入队。失败的可以再下。批量对话框里这些集，以及打开时就能判断的磁力 / m3u8 / DASH，置灰、写出原因、不能勾选。全选、「下载本季全部」和「从当前集往后全部」都跳过它们。Emby 是否只允许转码要等取地址才知道，那种仍在入队时跳过并写进汇总。
- 批量在下载线程上逐集解析，主线程只更新「正在加入下载队列…」和最后的汇总。取消时，已经解析好的会入队，还没解析的不加。汇总为「已加入 n 集，跳过 m 集」，并按原因计数。汇总里的 http(s) 地址只留主机名，磁力不留哈希。
- 新的一批排在已有队列后面，批内顺序与选集顺序一致（数组仍是下标 0 最新、从末尾往前找排队项）。播放页入队不调用暂停、关闭或重开播放器。播放页不调用 `requestPermissions`；Android 13 的通知权限框会让播放器 onPause，内置播放会暂停并向 Emby 上报暂停。需要时记下 `download.notifyDeferred`，回到首页、Emby 详情、影视仓详情或离线下载页再问。已经问过或已经授权不再问。
